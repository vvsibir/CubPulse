## Проект

HTML5-клон CubPulse, **single-file-free**: нет внешних файлов и ассетов —
звук процедурный (Web Audio API), графика рисуется на canvas.

## Среда разработки (важно)

- **Браузер к сессии, как правило, НЕ подключён** — на слух/глаз ничего не проверить.
  Приёмка только:
  1. `node --check game.js`
  2. `node tools/sound_test.js && node tools/game_input_test.js && node tools/levels_select_test.js`
     (сейчас: 18 + 24 + 8 = 50 OK, все зелёные)
- Ручная проверка в браузере (если появится): `node tools/serve.js`.
- Синхронные копии инструментов держатся в рабочем кеше сессии — обновлять после правок
  (иначе в сообщениях отстают).

## Жёсткие правила (не нарушать)

1. **Один тач = один прыжок.** Pointer Events, `preventDefault`, запрет выделения и
   контекстного меню на канвасе/оверлеях.
2. **Музыка начинается с первого тапа** (состояние `ready`: мир заморожен до первого
   касания), обрывается при смерти (`musicCut`), возобновляется при рестарте.
3. **После КАЖДОГО коммита — сразу `git push origin main`.** Никогда не оставлять
   запушенные коммиты только локально.
4. **Инвариант генератора:** `node tools/gen_levels.js` обязан воспроизводить
   `level-4.js…level-20.js` байт-в-байт, кроме задуманных изменений. Любая правка
   уровней-4-20 делается через генератор (+ тест), а не руками; после прогона проверять
   `git status`/`git diff`, что изменился только нужный файл.
5. **Коммитить только по явной команде пользователя.** Он говорит «пока не комить» —
   оставить в рабочем дереве, «закомить» — коммит (при желании — раздельными
   коммитами по смыслу) и сразу push.
6. Спрашивать при неоднозначности: музыкальные правки («продли/ускорь/сделай...») и
   геометрия уровней часто допускают разные трактовки — уточнять через `question` с
   конкретными вариантами, не гадать.

## Ключевые константы движка (`game.js`)

- `CONFIG.SPEED = 480` px/с, `GRAVITY = 2800`, `JUMP_VELOCITY = -900`
  → прыжок: высота ~144 px, дальность ~309 px (лимит для геометрии уровней).
- `GROUND_Y = 640`.
- `TOTAL_STEPS = 64` — базовая длина петли (4 такта × 16 шагов); тема может задать свою
  длину через поле `steps` (у neon — 128).

## Музыкальная система

- `MUSIC_RECIPES` (строки ~310-318) → `MUSIC[key] = makeMusic(bpm, root, mode, deg, arp, mel, mel2)`.
- **`makeMusic(bpm, root, mode, degrees[4], arpPat, melPat, melPat2)`** — каждая ступень даёт
  аккорд `{bass, arp, pad, mel}`; возвращает `{bpm, chords, steps: chords.length * 16}`.
  - `melPat2` — «продолжение мелодии»: число = один мелодический паттерн на все 4 такта
    продолжения; **массив из 4 = свой паттерн на каждый такт** (у neon `[0,0,0,4]`).
  - Паттерны `mels[]`: 0 — основная фраза, 4 — «как основная, но другая концовка»
    (последняя нота — квинта `t5+12` вместо тоники `r+12`).
- **`Sound.setMusic(id, speed = 1)`**: `_stepDur = 60 / bpm / 4 / speed`,
  `_steps = m.steps || TOTAL_STEPS`; планровщик `_tick()` зацикливается по `_steps`.
- `level.musicSpeed` передаётся из конструктора Game (строка ~779):
  `this.sound.setMusic(this.level.music || this._levelTheme().music, this.level.musicSpeed || 1)`.
- **Уровень 17 сейчас:** `music: 'neon'` (152 BPM, major, root 48, deg [0,5,4,5]),
  `musicSpeed: 2`, `mel2: [0,0,0,4]` → 8 аккордов / 128 шагов, цикл ~6.3 с: такты 4-6
  повторяют первую фразу, такт 7 — та же фраза, но концовка на квинту.

## Yandex Games SDK (интеграция)

- **Лоадер — в `gm-1.html`** (в `<head>`): асинхронно грузит `https://yandex.ru/games/sdk/v2`,
  после `YaGames.init()` кладёт `ysdk` в `window.ysdk` и вызывает
  `ysdk.features.LoadingAPI.ready()`. Вне платформы (локально/GitHub Pages) `YaGames` не
  загрузится — игра работает без SDK, все вызовы защищены.
- **`game.js`** — только защищённые вызовы через `window.ysdk` (гварды `_ygAPI/_ygStart/_ygStop`):
  - `GameplayAPI.start()` — первый тап (`ready→playing`) и `restart()`.
  - `GameplayAPI.stop()` — смерть (`kill()`) и победа (`won`).
  - `visibilitychange`: скрытие вкладки → `stopMusic()` + `GameplayAPI.stop()`;
    возврат (если `playing`) → `startMusic()` + `GameplayAPI.start()`. Требование «звук вне игры».
- Реклама/лидерборды/сохранения НЕ подключены (вне scope).
- Тесты не затрагивают лоадер (он в gm-1.html, тесты эвалят только game.js);
  в `game_input_test.js` `window.ysdk` отсутствует → все `_yg*` — no-op.

## Уровень 17 — геометрия шипов

- 7 низких платформ `y=560`; под каждой — ряд свисающих шипов
  `{type:'spike', y:580, w:40, h:40, flip:true}` (apex 620, т.е. ~20 px над землёй 640).
- **21 шип — по 3 в ряду** (было 4). Ряд 120 px по центру платформы:
  в генераторе `start = Math.round(p.x + (p.w - 120) / 2)`, цикл `i < 3`.
- Эти шипы — ручная инъекция в генераторе (`if (id === 17) { ... objs.sort((a,b)=>a.x-b.x); }`),
  остальная геометрия — секции `makeSections`.

## Game over / меню

- `#menu` — full-screen оверлей; показывается при победе и после смерти (задержка 0.3 с).
- Кнопок «Заново» НЕТ. На экране смерти: кнопки «Следующий»/«Выбор уровня» — и тап-рестарт
  мимо кнопок: на `#menu` висит `pointerdown`, срабатывает при
  `state === 'dead' && deathTimer > 0.4 && e.target === this.menu` → `onPressStart()`.
- Поле `this.menu` — сам элемент `#menu`; `e.target === this.menu` отличает тап мимо кнопок.

## Типовой цикл правки уровня

1. Понять требуемое; при неоднозначности — уточнить вопросом.
2. Правка в `tools/gen_levels.js` (генерация/инъекция) + при необходимости в тесте.
3. `node tools/gen_levels.js` → проверить `git status`: из level-4..20 меняется только
   задуманный файл, `git diff` ровно тот.
4. Обновить/добавить проверки в `tools/game_input_test.js` или `tools/sound_test.js`.
5. `node --check game.js` + все три теста — должны быть зелёными.
6. **Не коммитить**, пока пользователь не скажет «закомить» (он любит сначала послушать).
7. По команде — коммит (смысловыми порциями) + сразу `git push origin main`.
