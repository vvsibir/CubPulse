# tools/ — скрипты разработки

Инструментарий проекта `gm-jump`: тесты движка, генератор уровней 4-20 с валидатором
и вспомогательные утилиты. Все пути внутри скриптов относительные (`__dirname`),
поэтому папку можно переносить вместе с репозиторием.

## Тесты (запуск: `node tools/<файл>`)

| Файл | Что проверяет |
| --- | --- |
| `sound_test.js` | Sound-модуль: unlock/startMusic/musicCut, SFX, мьют, секвенсор, все музыкальные темы и темпы, реестр THEMES.default |
| `game_input_test.js` | Интеграция: Pointer Events (один тап = один прыжок), состояние ready (музыка с первого тапа), выбор `?level=N`, меню победы (смерть — рестарт тапом, масштабирование кнопок под канвас), пер-уровневые темы, отрисовка, все 20 скриптов в gm-1.html, демо-бот фрейм-независим (level-17 при 30/60/120/144 Гц через `loop()`), демо-бот по всем 20 уровням, сохранение `?mode=` в навигации, демо-цикл (победа → следующий уровень, после 20-го — первый), реклама Яндекс на каждую 5-ю смерть |
| `levels_select_test.js` | Экран выбора: явные теги level-1..20.js без авто-пробы (нет 404), 20 карточек, палитры, время/объекты/темы, проброс `?mode=` |

Прогон всех тестов:

```
node tools/sound_test.js && node tools/game_input_test.js && node tools/levels_select_test.js
```

## Генератор и проверка уровней

- `gen_levels.js` — детерминированный генератор уровней 4-20 (seed `id*7919+13`),
  с валидатором достижимости (зазоры платформ, кластеры шипов ≤ 4, вершины башен)
  и блоком «добивки хвоста» (одиночные шипы с шагом 400 px от последнего препятствия
  до ~700 px перед воротами — укорачивает «пустые» финишные участки).
  **Внимание:** при запуске перезаписывает `level-4.js … level-20.js` в корне проекта.
  Проверено: текущая версия воспроизводит закоммиченные уровни байт-в-байт.
- `levels_check.js` — зеркало логики `index.html` для браузера: карточки 1..20 без авто-пробы
  в Node с моком DOM.

## Утилиты

- `serve.js` — локальный статический сервер для ручной проверки в браузере:
  `node tools/serve.js` → http://localhost:8097 (главная — `gm-1.html`, выбор — `index.html`).

## Релиз

- `release.js` — сборка папки `Release/` в корне проекта: копирует туда **только
  нужные для игры файлы** (`gm-1.html`, `index.html`, `game.js`,
  `level-1.js … level-20.js`) и удаляет из них **все комментарии**
  (JS: `//` и блочные; HTML: `<!-- -->` и комментарии внутри `inline-<script>`).
  После сборки проверяет синтаксис всех выпущенных JS (`node --check`, включая
  inline-скрипты HTML) и выводит сводку. Запуск: `node tools/release.js`.
  Папка `Release/` добавлена в `.gitignore` — результат сборки не коммитится.
  Подводный камень: стриппер не знает regex-литералы — в inline-скриптах HTML
  **нельзя** использовать regex, содержащий `//` (например `/^https?:\/\//`):
  он будет принят за line-комментарий и обрежет строку. Пишите такие regex
  через split/строки или без последовательности `//` внутри литерала.
